# Research decisions — 24 October 2026

The update uses current primary documentation plus observed problems in this collection. Research informs changes; it is not evidence that our trials passed.

- [OpenAI skill guidance](https://learn.chatgpt.com/docs/build-skills): implicit selection uses the description and progressive loading. Keep the namespace and descriptions focused; add metadata-only selection trials. Current docs list `.agents/skills` for user/repository discovery. Installed versions and existing supported roots must be checked before choosing installation locations; do not add duplicate copies merely because another alias exists.
- [Agent Skills authoring guidance](https://agentskills.io/skill-creation/best-practices): extract workflows from real tasks, match control to fragility, and validate actual execution. The accepted retro overviews supply a concrete new skill; no general-purpose mandatory router is needed.
- [Agent Skills evaluation guidance](https://agentskills.io/skill-creation/evaluating-skills): evaluate observable outputs with representative cases. Separate discovery decisions, report generation, and deterministic installer/structure tests; disclose unexercised criteria.
- [Claude Code skills](https://code.claude.com/docs/en/skills): personal skills use `~/.claude/skills`; host-specific metadata and invocation features need not be imposed on portable instructions. Preserve the supported standard frontmatter and existing automatic discovery policy.
- [Gemini CLI skills](https://geminicli.com/docs/cli/skills/): user skills use `.gemini/skills` or the shared `.agents/skills` alias, with precedence on duplicate names. Verify discovery with the installed CLI and avoid new aliases without a concrete need.
- [Cursor skills](https://cursor.com/docs/skills): user skill discovery includes Cursor and compatibility directories; local skills are not automatically deployed to remote/cloud agents. This task updates installed local CLI skill roots, not remote accounts or plugins.

The map and review improvements address source drift, redundant base questions, unconditional reviewer cost, and unobservable routing. Independent high-risk review, actual evidence, explicit delivery boundaries, and the target-based Windows policy remain intact. Tool/model availability is taken from the live runtime rather than cached vendor claims.
