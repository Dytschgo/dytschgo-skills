# Dytschgo Retro

If `references/active-profile.md` exists, read it as this installation's selected working profile. Apply relevant defaults under the current task instructions.

Turn evidence or a settled explanation into a useful interactive HTML overview. Use the user's source material and requested scope. The presentation does not prove the underlying work or authorize implementation, publication, or deployment.

## Choose the content

Identify the reader's decision: understand a change, compare options, inspect a project route, or assess review findings. Inspect the relevant sources first. Preserve their exact design IDs, revisions, states, and uncertainty. Label examples and proposed routes; distinguish observed results, source inspection, and expected benefits.

For a requested code review that has not been performed, use [Dytschgo Review](../dytschgo-review/SKILL.md) for the technical assessment, then present its actual findings. Existing qualifying review evidence can be presented without repeating the review. For product UI implementation rather than a report, use [Dytschgo Design](../dytschgo-design/SKILL.md).

## Build the overview

For a substantial audit report, adapt the [decision-focused report template](assets/audit-report-template.md). It separates defects, improvement options, coverage limits and owner decisions, retaining finding IDs and challenge verdicts. Use supplied evidence; the template does not start another audit or authorize implementation.

Read [presentation and delivery](references/presentation.md) for the renderer and checks. Adapt [the console shell](assets/console-shell.html) when useful; replace its demonstration data with supported content. Keep system fonts, inline CSS/JavaScript, and no required network dependencies.

Use a restrained retro console: monospace labels, amber/cyan accents, clear panel hierarchy, and subtle static texture. Preserve readable body text. Choose controls that help inspect real information: project-start selectors, before/after details, filters, skill inspectors, or evidence disclosures. Keep the main takeaway visible without clicking. A simple explanation can stay short.

## Complete

Exercise the meaningful controls and inspect desktop and narrow rendered views. Check the correct selection, accessible names, keyboard reachability, content wrapping, and page overflow. Preserve reduced-motion usability. Source and evidence links must match their claims. Record any untested behavior or unavailable renderer. Save the self-contained HTML artifact, render inline when supported, and give a concise completion response. A review alone ends at findings; do not silently fix the reviewed work.
